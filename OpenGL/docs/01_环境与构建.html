合集中的 OpenGL 构建入口

本页保留原独立工程的背景说明。在新合集内请优先从仓库根目录执行 cmake --preset opengl、cmake --build --preset opengl-debug 和 ctest --preset opengl-debug。 根配置已使用 OpenGL/build；若按旧说明独立配置子工程，必须另设 OpenGL/build-local，避免 source root 冲突。旧 build.ps1 入口已转发到合集脚本。

环境与构建

Windows

要求：CMake 3.24+，Visual Studio 2022 的“使用 C++ 的桌面开发”（包含 MSVC 和 Windows SDK），支持 OpenGL 3.3 Core 的显卡驱动。本工程用 C++17，GLFW 和 GLAD 部分源码是 C，所以 project 同时启用 C/CXX。

从 OpenGL 打开终端。cmake --preset windows-vs2022 生成工程，cmake --build --preset debug --parallel 编译。首次会编译 GLFW，后续只增量构建。仅构建一课：

cmake --build build --config Debug --target 05_texture --parallel
.\build\bin\Debug\05_texture.exe

Release 用 cmake --build --preset release --parallel，程序位于 build/bin/Release。不要把 Debug 与 Release 的输出路径混淆。打开 build/OpenGLCourse.sln 可使用 Visual Studio 调试；也可以用 VS“打开文件夹”载入 OpenGL，让它读取 CMakePresets.json。断点优先设在 main.cpp 的 draw 前。

验证

ctest --preset smoke

每个程序用隐藏窗口创建真实 OpenGL 上下文，执行四帧并检查 GL 错误与画面是否包含几何；第 01 课只检查清屏。它不是软件渲染替代品，仍需可用图形驱动。无显示服务器的 Linux、受限远程桌面和 CI 可能无法创建上下文。

Linux / macOS（源代码兼容，当前机器未验证）

Linux 先安装编译器、CMake、Ninja 和发行版的 X11/Wayland 开发库。Ubuntu 可从 build-essential、ninja-build、libxrandr-dev、libxinerama-dev、libxcursor-dev、libxi-dev、libwayland-dev、libxkbcommon-dev、wayland-protocols 开始，根据 GLFW 检测日志补充。也可配置 -DGLFW_BUILD_WAYLAND=OFF 只用 X11。macOS 安装 Xcode Command Line Tools、CMake/Ninja；程序已设置 forward-compatible context。

cmake --preset ninja

继续构建并运行：

cmake --build build-ninja --parallel
./build-ninja/bin/02_triangle
ctest --test-dir build-ninja --output-on-failure

不要在同一 build 目录里切换生成器或移动源码路径；换用新的目录，例如 cmake -S . -B build-other -G Ninja。构建缓存内含绝对路径，拷贝整个工程到其他目录后请重新配置到新的构建目录。
