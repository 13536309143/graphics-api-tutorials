排错手册

现象检查顺序
找不到 C/C++ 编译器VS Installer 是否包含“使用 C++ 的桌面开发”；重新配置生成器
生成器与缓存冲突不混用旧 build，指定新的 -B 目录
无法创建上下文查看 GLFW 错误；更新显卡厂商驱动；本地登录重试，排除远程会话限制
Missing shader重建目标，确认 exe 旁有 shaders/，整目录复制程序
GLSL 编译失败读取控制台日志中的源码行号、变量类型和版本；本工程使用 #version 330 core
黑屏先第 01 课确认清屏，再检查 viewport、VAO、shader、MVP、顶点范围、深度与纹理
纹理全黑sampler 单元编号、绑定、mipmap、上传格式；不是把对象 id 直接设为 sampler
模型拉伸用实际 framebuffer 宽高比，排除整数除法
物体互相穿透启用 GL_DEPTH_TEST，并且每帧清除深度
光照跟相机乱动确认 N/L/V 都在同一空间并且归一化
后处理全黑FBO 完整性、附件尺寸、第二遍程序/纹理/深度状态、不能读写同一纹理
阴影条纹或悬浮调整 bias、缩紧光源视锥、检查深度映射与 viewport 恢复

GL 错误编号：1280=GL_INVALID_ENUM，1281=GL_INVALID_VALUE，1282=GL_INVALID_OPERATION，1285=GL_OUT_OF_MEMORY，1286=GL_INVALID_FRAMEBUFFER_OPERATION。本工程在帧尾检查错误，因此编号指向的是这一帧某次调用；需要精确定位可在可疑调用后临时加检查。

诊断时从一个已验证的简单输出开始：片段 shader 固定输出红色；顶点 shader 只输出可见 NDC 三角形。若能看见，再逐步恢复矩阵、纹理和光照。不要同时修改全部模块。

进阶调试可用图形帧抓取工具查看 draw、管线状态和附件。OpenGL 3.3 Core 不保证有 KHR_debug；使用调试回调前必须检测扩展/更高版本并生成相应 GLAD 接口，不能直接在当前最小接口上调用未加载函数。
