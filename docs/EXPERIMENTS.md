# 三 API 统一实验协议与记录表

对照的目标是解释责任和数据流。把不同场景截四张图放在一起，可以展示效果，但不足以证明像素等价或性能差异。本页给出可反复执行的八组实验；其中带“迁移设计”的部分需要先实现，不宣称已经自动完成。

## 先保存基线

记录提交号、设备/驱动、配置、分辨率、相机、时间、shader 参数与是否开启垂直同步。先运行已有 smoke，确保原场景有效，再只改一个因素。每次保存预测、结果和解释；恢复基线后再开始下一个实验。

| 实验 | 控制变量 | 观察证据 | 合格结果 |
| --- | --- | --- | --- |
| A 初始化与呈现 | 设备、窗口大小、背景色 | 日志、清屏、退出与 resize | 对象层次可解释，无初始化错误 |
| B 三角形 | 固定位置、固定输出洋红 | draw 事件、VS 输出、颜色目标 | 能区分输入、管线和呈现失败 |
| C 几何布局 | 同一 Vertex/indices | mesh viewer、stride、offset | 32 字节 / 0、12、24 与输入对应 |
| D 每帧/每对象 | 固定相机、两个对象 | UBO/CBV 与 push/root 内容 | 改一个对象不影响另一个 |
| E 纹理链路 | 同一四象限图、相同 sampler | upload bytes、row pitch、view | 方向、颜色与采样约定一致 |
| F 深度/离屏 | 相交几何、固定投影 | depth target、state/layout、最终图 | 遮挡正确，resize 后仍成立 |
| G 计算结果 | 同一 N 与公式 | 全量数值、组大小、完成条件 | vk/nv/dx 逐项正确；GL 当前不覆盖 |
| H PBR / 多遍 | 统一光照和颜色链路 | N、NoL、D/G/F、各中间纹理 | 先对齐输入，再讨论剩余差异 |

## A—F 的执行方式

从[对照实验室](compare/index.html)选择相应主题，先运行默认 Debug 示例并记录结果。OpenGL、Vulkan、DX12 的 geometry/transform 课不一定是同一个场景；严格比较前按章节建议统一输入。nvpro 在可交互视口中输出，须把视口尺寸也纳入记录，而不是只记录外层窗口大小。

纹理测试先用四象限颜色判定方向，再用棋盘查看过滤，最后检查 sRGB。深度测试先固定模型不动，确认清除值与比较函数，再恢复动画。每一阶段证据成立后才进入下一阶段。

## G 的边界与尾部测试

先用现有 N=256，确认 64 线程×4 组及所有结果正确。扩展到 257 时同时改变容量、组数、shader 上界和 CPU 参考循环。再改公式为 3*i+7，故意只改一端以证明验证能失败，然后修正两端。OpenGL 的 3.3 路线没有计算课，不拿实例粒子替代此测试。

## H 的分级目标

直接光 PBR 可以先在 vk09 与 dx09 之间对齐共享输入，再把 nv06 的 UI 倍率固定，最后把 OpenGL 场景调整到相同光源/相机并关闭 IBL。当前截图不能默认逐像素一致，栅格化细节和浮点差异也需设置合理容差。

迁移 IBL/SSAO 时，按中间产物分别验收：每个 cubemap 面、粗糙度 mip、BRDF LUT、位置/法线 G-buffer、原始 AO、降噪 AO 和最终合成。它们在显式后端当前属于设计任务。

## 性能实验另立条件

本项目尚无统一跨 API benchmark。要比较耗时，先功能对齐，再使用 Release 和相同工作量；预热、重复采样，分别报告 CPU、GPU 和整帧时间。排除 shader 编译/资源创建，并记录串行等待和 UI 成本。不要以本次 Debug smoke 用时推断 API 性能。

## 新增 54 课的图像对照工具

新增静态 OBJ、glTF 节点、GPU 粒子和综合场景使用相同 CPU 场景/固定输入。先运行 21、22、29、36 的 `--smoke`，再执行 `python tools/compare_readbacks.py`，按 0..255 通道单位比较两后端 PPM 的平均绝对误差。此工具检查画面，不测量性能；默认容差可用 `--max-mean-error` 调整。

直接裁剪空间的粒子路径在 Vulkan 绘制矩阵中显式翻转 Y，以对齐 DX12。MSAA/过滤/浮点在不同实现间可能产生差异，因此本机通过不等于所有 GPU 必须逐字节一致。颜色空间、帧输入和尺寸不一致时先修正实验条件。
